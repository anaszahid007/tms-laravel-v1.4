# Implementation Plan - Manual Payment Proof System

This document outlines the plan to build a "Proof of Payment" subscription workflow tailored for the Pakistani market (JazzCash/EasyPaisa/Bank).

## 1. Database Schema Changes
We need to track the proof details.

### A. Update `user_subscriptions` table
- Add column `payment_proof_path` (string, nullable) - To store screenshot.
- Add column `transaction_id` (string, nullable) - Manual Trx ID input.
- Add column `admin_notes` (text, nullable) - Rejection reason if needed.
- Ensure `payment_status` enum supports: `pending`, `approved`, `rejected` (It matches current logic).

---

## 2. Shop User Experience (The "Organic" Flow)
We will create a seamless checkout experience.

### A. `SubscriptionController@checkout` (View)
- Show Plan Details clearly.
- **Payment Methods Card:**
  - Tab 1: **JazzCash** (Number & Name)
  - Tab 2: **EasyPaisa** (Number & Name)
  - Tab 3: **Bank Transfer** (Account Details)
- **Action:** A Clean Form below details.
  - "I have sent the payment"
  - Input: Transaction ID.
  - Upload: Screenshot.
  - Button: "Submit Verification".

### B. `SubscriptionController@store` (Logic)
- Validate inputs.
- Create `UserSubscription` record with status `pending`.
- Store uploaded image in `storage/app/public/payment_proofs`.
- Redirect User to a "Waiting for Approval" Dashboard state.
  - *Crucial:* If status is `pending`, accessing the dashboard should show a banner "Your payment is being verified". They normally can't use the app yet (or can use limited features).

---

## 3. Admin Experience (The "Efficiency" Flow)
You need to approve these fast.

### A. `Admin/SubscriptionController`
- **Dashboard Widget:** "Pending Approvals (3)" with a Red Badge.
- **Approvals List Page:**
  - Table showing: Shop Name, Plan, Date, Trx ID.
  - **Action:** "View Proof" (Opens Modal/New Page with Image).
  - **Buttons:**
    - ✅ **Approve:** Activates subscription, triggers Referral Logic (Phase 4), Sends Email to User.
    - ❌ **Reject:** Mark rejected, set reason, Email User to try again.

---

## 4. Execution Steps

1. [ ] **Migration:** Add proof columns to `user_subscriptions`.
2. [ ] **Controller:** Create `Shop/SubscriptionController` for checkout & submission.
3. [ ] **Views:** Design the "Checkout" page (Focus on Trust & Clarity).
4. [ ] **Admin:** Create the Verification Interface.
5. [ ] **Logic:** Implement the Approval/Rejection hooks (referral engine trigger).
