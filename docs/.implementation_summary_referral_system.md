# Implementation Plan - Referral System (MVP)

This document outlines the step-by-step plan to implement a robust Referral Application logic for TailorOnDesk.

## 1. Database Schema Design
We need new tables to manage partners, track commissions, and handle payouts.

### A. `referral_partners` table
Stores the influencers/partners promoting the platform.
- `id` (UUID)
- `name` (String)
- `email` (String, Unique) - Used for login/contact
- `phone` (String)
- `referral_code` (String, Unique, Index) - e.g. "ALI2026"
- `commission_type` (Enum: `percentage`, `fixed`)
- `commission_value` (Decimal) - e.g. 20.00
- `duration_type` (Enum: `forever`, `one_time`, `limited`)
- `duration_limit` (Integer, nullable) - Number of payments to reward (if limited)
- `status` (Enum: `active`, `suspended`)
- `timestamps`

### B. `referral_conversions` table
Tracks which shop signed up using which code.
- `id` (UUID)
- `referral_partner_id` (FK)
- `shop_id` (FK) - The shop that was referred
- `converted_at` (Timestamp)

### C. `referral_earnings` table
Logs every single commission earned event.
- `id` (UUID)
- `referral_partner_id` (FK)
- `conversion_id` (FK)
- `amount` (Decimal) - The commission amount earned
- `order_amount` (Decimal) - The amount the shop paid (for reference)
- `status` (Enum: `unpaid`, `paid`)
- `timestamps`

### D. `referral_payouts` table
Logs actual payments made to partners.
- `id` (UUID)
- `referral_partner_id` (FK)
- `amount` (Decimal)
- `method` (String) - e.g. "Bank Transfer"
- `reference_id` (String) - Transaction ID
- `paid_at` (Timestamp)

---

## 2. Model & Logic Setup
- Create Models: `ReferralPartner`, `ReferralConversion`, `ReferralEarning`, `ReferralPayout`.
- Define Relationships:
  - `Shop` belongsTo `ReferralPartner` (optional/through conversion).
  - `ReferralPartner` hasMany `ReferralEarnings`.

---

## 3. The "Tracking" Implementation (Middleware)
- **Cookie Logic:** Create a middleware `TrackReferral`.
- **Logic:**
  1. Check for `?ref=CODE` in URL.
  2. If found, Validate code against Database.
  3. Store `referral_code` in a Cookie (Valid for 30 days).

---

## 4. Registration Hook
- Modify `RegisteredUserController@store`.
- **Logic:**
  1. Check for `referral_code` cookie.
  2. If exists, find Partner.
  3. Create `ReferralConversion` linking the new `Shop` to the `ReferralPartner`.

---

## 5. Admin Panel (Management)
- **Partner CRUD:** Create, Edit, Delete Partners. (Set rates/codes).
- **Dashboard:** Show "Total Referred Shops", "Pending Commissions", "Total Paid".
- **Payouts:** Button to "Pay Partner" which calculates unpaid earnings and marks them as paid.

---

## 6. Partner Dashboard (Simple)
- **Route:** `/partner/login` (Separate simple guard or share User model with role='partner').
- **View:** See their own Link, Stats (Clicks/Signups), and Earnings History.

---

## 7. Commission Calculation Logic (The "Engine")
- **Trigger:** When a `UserSubscription` payment happens (mocked or real).
- **Service:** `ReferralService::calculateCommission($payment)`.
- **Logic:**
  - Find referrer.
  - Check duration logic (Is it their 1st payment? 5th? Is limit 1?).
  - Calculate Amount (`%` or `fixed`).
  - Create `ReferralEarning` record.
